# M8 companies, Customer 360 and merge (F3.01, F3.03)

Issues: FIG-1095 (F3.01, companies list C1 and Customer 360 C2) and FIG-1097 (F3.03, merge duplicates C4). Design: `design-spec/CrmCustomers.dc.html` (list, Customer 360), `CrmOverlays.dc.html` (merge sheet). Code: `src/ui/screens/customers/`, stylesheet `customers.css` (classes `fb-cu-*`; buttons, tabs, scope pill, drawer and modal reuse the Leads classes `fb-ld-*`, which carry the same design). Routes: `companies`, `companies/[companyId]`, `merge` (page frame only; the screens read the API).

## What is built

- **Companies list (C1, `CompaniesScreen`)**: heading, scope pill and role hint (Management "All organisation companies", editors "Shared list", view-only "Read-only"), four stat tiles (Companies, Customers, Prospects, Dormant), tabs All / My companies (editors) / Dormant / Archived with the API's counts, search, lifecycle filter, table (company and location, industry, lifecycle pill, contacts, owner, actions), paging 25/50/100, export CSV (`exportCompanyDirectory`, same filters), New company drawer, Import CSV sheet (`ImportCsvDialog`, 500 rows per request, progress, results), row Merge and Archive (with a confirmation and an Undo toast) and Restore on the Archived tab. Owner is a picker for roles that may reassign (`companies.edit` plus `membership.manage`), text for everyone else. States: loading skeleton, no companies, no results (with Clear filters), error with Retry, explained no-access on 403.
- **Customer 360 (C2, `CompanyDetailScreen`)**: one `getCustomer360` call; each part is its own section with its own status. Header (initials tile, name, lifecycle pill, industry and location, scope pill) and actions (Log activity, New deal, Edit, Merge, Archive, each only when the role may). Summary tiles: Lifecycle (a control for editors, text otherwise), Next follow-up, Open deals, Won to date, Outstanding, Owner. Panels: Services and projects (company services and recurring services with the renewal state), Requirements (from handoffs), Deals, quotes and proposals, Communication and activity (timeline with "Show older" paging by the API's cursor), Contacts (call and WhatsApp through the contacts area's `ReachButtons` and `useCallLogPrompt`, so the log prompt follows the call), Tasks, Outstanding issues, Payments, and the shared `RecordExtras` panel (tags, custom fields, attachments, comments, follow, health) mounted with `kind="company"`.
- **Lifecycle**: changing the state asks for a reason (the API requires one), shows an Undo toast, and marks the state "Set by hand; the daily check leaves it alone" with **Let the system decide** (`releaseCompanyLifecycle`). Dormant Customer and Active Customer come from the lifecycle engine, not from the screen. The Customers and Prospects stat tiles count by lifecycle state through the directory.
- **Archived**: banner "Archived. Everything on this customer is read-only until it's restored." with Restore for roles that may archive; no edit, merge, log or lifecycle controls; `RecordExtras` is passed `archived`. A merged-away company says where it went.
- **Merge (C4, `merge/MergeDialog`)**: `MergeDialog({ kind: "company" | "contact" | "lead", id, onClose?, onMerged? })`, opened from the company row, Customer 360, and (by the contacts area) the contact page. Steps: pick the duplicate (likely duplicates from the duplicate check first, then a search of the directory), compare side by side (THIS RECORD / POSSIBLE DUPLICATE, choose which is kept), choose the value of every field that differs (the default keeps the kept record's value and fills a blank from the other), read the preview sentence, confirm. Result: the other record is archived (never deleted), contacts, deals, tasks and timeline move across, the audit log gets `company.merged` / `company.merged_from` (or the contact equivalents), and the dialog stays open with **Undo merge** until the server's undo window ends (`postMergesByMergeIdUndo`). A refusal is explained in the dialog and nothing is lost. `/merge?kind=…&id=…` shows the same dialog as a page (used for links and tests).

## Masking and access

Nothing is computed from a masked value. A masked deal shows "Value hidden", "Won to date" and "Open deals" say "Values hidden" when any value in the group is masked, and the sums are never taken over a partly masked list. Recurring-service values follow the API's masking. The **Payments panel exists only when the API answers `payments` as `ok`** (Finance and Management); every other role sees "Finance only / Ask Finance" in the Outstanding tile and no payment, invoice number or amount anywhere on the page. A section the API refuses (`no_access`) is explained with the reason and the roles that own it (for Finance: Tasks and Communication). Technical gets the explained no-access page.

## Decisions taken without asking

1. **No Customers tab and no DEALS column on the list.** The directory API has tabs ALL, DORMANT and ARCHIVED only, filters by one lifecycle state, and returns no per-company deal count. The Customers *tile* is the sum of four counts by state (Customer, Onboarding, Active Customer, Renewal); the tab became a **Lifecycle filter** (any single state). The Deals column is left out rather than shown as a dash.
2. **Leads are not merged.** The frozen V1 contract has merge routes for companies and contacts only. For a lead the dialog explains that, and points to merging the company or contact. If lead merge is wanted it is a backend change and a contract change (Given's call).
3. **New deal** on a company links to the deals board; the board has no company pre-fill yet.
4. **Import CSV** is a sheet on the list (`ImportCsvDialog`, usable for contacts too), not a link to the data-migration wizard (M9), so the button works today.
5. **Export** uses the directory export (same filters as the list) and does not offer the bulk-approval path; above the bulk limit the API says so and the toast shows it.
6. **Health score** is shown by the shared extras panel (agent F3.08), not duplicated on the page.
7. **Tickets and the survey** are Customer Support (V1.1): "Outstanding issues" says nothing is outstanding and shows the API's `not_available` reason.
8. **Merge field defaults**: because the API ignores its fill-blanks rule once `fields` is sent, the dialog sends an explicit choice for every field.

## Known gaps

- Sort on the list columns (the design has none) and a Deals count per company (not in the API).
- Merge shows only the fields the merge API can choose between; relations (contacts, deals) always move to the kept record, as the API does.
- The "Show older" timeline loads the next page of the timeline only; filters by kind are not offered (the design has none).
