## Findings for Given (no test written, no code changed)

1. **Sequence SEND steps do send mail.** `src/sequences/engine.ts` sends an approved template through `sendAndLogEmail` when Management chose `emailMode: "SEND"` and every merge field is filled. Rule 9 lists "draft" for automations, and the issue says automations may draft but never send. Existing tests (`tests/followUpSequences.test.ts`) deliberately expect the send, and it goes through the SMTP or log transport, not a person's connected mailbox. It is Management's explicit choice per step and never moves a deal, but Given should confirm that this is the intended reading of rule 9. The rule catalogue in `src/automations/` itself cannot send (newly tested).
2. **Plain text figures in chat are not redacted in the message list.** By code reading (`src/services/chatService.ts`, `presentMessages`), `moneyHidden` applies only to a record channel, a DEAL card or an INVOICE card. A figure typed in an ordinary channel with no card (for example "Quote is KES 90,000") is shown as typed to Delivery in the message list and search, while the notification for the same message is redacted (`tests/chat.test.ts`). Not asserted in a test because the intended behaviour is Given's call: either redact free text for everyone without `deals.view.value`, or accept that typed text is the author's responsibility.
3. **Mail and meeting text on timelines is shown as written.** `listCommunicationsFor*` does not pass text through `textForViewer`. Synced customer mail that quotes a price is visible to every role that may open the record and holds `communications.view`. Access to the record is checked (tested); text redaction is not applied. Same decision as finding 2.
4. Notifications are not generated by mail or calendar sync; only chat mentions and direct messages notify (covered).
